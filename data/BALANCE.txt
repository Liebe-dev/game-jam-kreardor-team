Balance data ownership

data/units/*.tres: effective HP, melee/ranged/counter damage, impact damage,
movement/attack range, ammunition and reload values. Piece.definition is visible
in the Inspector. Unit identity uses UnitDefinition.Kind, independently of node names.

data/waves/wave_1.tres through wave_5.tres: enemy PackedScenes, grid positions,
survivor healing and replacement HP. The board's wave_definitions array is editable.

These files preserve the values actually used before this refactor. In particular,
the old Pawn.tscn damage=200 was not read by combat; its effective melee damage was
10. The new soldier definition records 10, preserving gameplay rather than enabling
the previously unused value. King's existing generic melee behaviour is preserved.

Definitions are shared immutable balance data. Current HP, ammunition, buffs,
positions and attack counts remain per-instance runtime state. Duplicate a definition
before changing it for one instance. Save checkpoints continue to use scene paths.

Spell data
data/spells/*.tres and catalog.tres contain all fourteen spell combinations.
power/duration/paper_cost/ink_reward/paper_reward are shared with the spellbook.
settings contains named per-spell mechanics such as tick_heal, tick_damage,
tick_ink, multi_target_reduction, directed_stun and impact_damage. Catalog controls
ink_cost_per_character and the existing multi_target_factor. Defaults preserve the
effective pre-refactor values. Book descriptions now report these effective values,
including earlier discrepancies such as Terra+Terra's two-turn, 50% shield.
